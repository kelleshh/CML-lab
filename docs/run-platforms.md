# Запуск CML-lab

CML-lab работает как локальный Python-сервис с интерфейсом в браузере. Установите **64-битный Python 3.12** с [python.org](https://www.python.org/downloads/), распакуйте архив целиком и запустите файл для своей системы. Python 3.12 — проверенная версия окружения; выбранный XGBoost 3.4.1 требует Python не ниже 3.12.

| Система | Обычный запуск | Диагностика |
|---|---|---|
| Windows | Двойной щелчок по `start.bat` | `diagnose.bat` |
| macOS | Двойной щелчок по `start.command` | `diagnose.command` |
| Linux | `start.sh` → «Запустить в терминале», либо `./start.sh` | `./start.sh --doctor` |

При установке Python на Windows включите **Add Python to PATH**. Системный Python автоматически не устанавливается. Запускатели сначала ищут готовое окружение `.venv`, затем установленный подходящий Python.

Первый запуск создает `.venv` в папке проекта и устанавливает библиотеки из `requirements.txt`. Нужны интернет, свободное место и доступ на запись в папку проекта. Установка может занять несколько минут. Следите за сообщениями в открытом терминале. Браузер открывается после успешного ответа сервера, а не после одного запуска процесса.

Признак готовности — строка `Готово: http://127.0.0.1:...` и страница CML-lab. Начальный порт — `8765`; занятый порт заменяется свободным. Повторный запуск из той же папки проекта с той же папкой данных открывает уже работающий сервис. Одну папку данных обслуживает только один сервер: запуск другой копии проекта с той же папкой отклоняется. Для независимого сервера задайте другую папку через `CML_LAB_DATA`; он получит свободный порт. Для остановки нажмите **Ctrl+C** в окне запуска. Закрытие вкладки браузера не останавливает Python-сервис.

## Команды

В терминале, открытом в папке проекта:

```bash
python run.py
```

На Linux/macOS имя команды может быть `python3`. Node.js для обычной работы не нужен.

| Параметр | Назначение |
|---|---|
| `--doctor`, `--check` | Проверить версии библиотек, доступность алгоритмов восьми задач и порт; не устанавливать библиотеки и не запускать сервер. |
| `--no-browser` | Запустить сервис без автоматического открытия браузера. |
| `--port 9000` | Начать поиск свободного порта с `9000`. |
| `--port 0` | Получить свободный порт от операционной системы. |
| `--system` | Использовать текущее окружение Python, пропустить автоматическую подготовку `.venv`. |
| `--host 127.0.0.1` | Привязать сервер к указанному адресу; по умолчанию доступен только этот компьютер. |

Пример для подготовленного окружения Linux/macOS:

```bash
.venv/bin/python run.py --system --no-browser --port 0
```

В Windows используйте `.venv\Scripts\python.exe`. Запускатель остается в терминале до остановки; он не устанавливает фоновую системную службу.

## Данные и переход с линейной лаборатории

По умолчанию данные, рецепты, запуски, эксперименты и журнал находятся в `~/.cml-lab`. Точный путь журнала выводится при запуске. Отдельную папку можно задать в переменной `CML_LAB_DATA` или файле `.env` в корне проекта:

```dotenv
CML_LAB_DATA=./data
```

Относительный путь отсчитывается от папки проекта. Файл `.env` читается как текст; уже заданные переменные окружения имеют приоритет. Старое имя `LINEAR_LAB_DATA` поддерживается как явный запасной вариант, если `CML_LAB_DATA` не задано. Старое имя папки `~/.linear-lab` автоматически не выбирается. Чтобы использовать прежнюю папку данных, укажите ее полный путь в `CML_LAB_DATA`.

Журнал `launcher.log` включает ошибки установки и запуска; его размер ограничен, сохраняются две предыдущие копии. Отправляйте журнал вместе с текстом ошибки, если нужна диагностика. Диагностика сообщает название недоступной модели и причину загрузки библиотеки.

## Если запуск не удался

| Сообщение | Действие |
|---|---|
| Нужен Python 3.12 или новее | Установите Python 3.12 и повторите запуск. Если `.venv` создана прежним Python, переименуйте эту папку, чтобы запускатель создал новое окружение. Пользовательские данные находятся отдельно. |
| Не удалось создать окружение | Проверьте доступ на запись. На Debian/Ubuntu Python может требовать пакет `python3-venv`; установку системного пакета выполняет администратор. Можно использовать уже подготовленное окружение с `--system`. |
| Не удалось установить библиотеки | Прочитайте ошибку pip выше и проверьте доступ к индексу пакетов. Повторный запуск использует кэш завершенных загрузок. |
| Папка данных уже используется другим сервисом CML-lab | Остановите первый сервер через Ctrl+C либо задайте отдельную папку в `CML_LAB_DATA`. Не удаляйте файл блокировки работающего сервера. |
| Браузер не открылся | Скопируйте адрес из строки `Готово:` в браузер. |
| LightGBM/XGBoost не загрузилась, указан `libomp` | На macOS проверьте OpenMP согласно инструкции библиотеки. Если Homebrew установлен, команда `brew install libomp` устанавливает нужную библиотеку; затем повторите диагностику. |
| Нет прав выполнения `start.command` или `start.sh` | В терминале в папке проекта выполните `chmod +x start.sh start.command diagnose.command`, затем повторите запуск. |

В Linux используется CPU-пакет `xgboost-cpu==3.4.1`; он не требует установки CUDA для работы лаборатории. В Windows/macOS используется `xgboost==3.4.1`. Выбор выполняют платформенные условия в requirements, а вычисления в каталоге настроены на CPU. LightGBM и CatBoost также выполняются как локальные библиотечные адаптеры.

Проверены Linux x86_64 и CPython 3.12: требования среды, диагностика, POSIX-сценарии и управление локальным сервером. Распакованная копия из ZIP запускается из папки с пробелами и символом `&` с уже подготовленным окружением; повторный запуск использует тот же процесс, другая папка данных получает отдельный сервер. Другая копия проекта с занятой папкой данных получает понятную ошибку; первый сервер продолжает работать, его файл состояния не меняется. Диагностика второй копии проверяет библиотеки и порт без запуска сервера. При Ctrl+C запускатель дожидается завершения Python и удаления файла состояния сервера. Эта проверка использует `--system` и не подтверждает установку зависимостей из пустого окружения без интернета.

Запуск Windows/macOS нужно проверять на соответствующей ОС; проверка платформенных условий и наличие опубликованных wheels не подтверждают такое выполнение. `start.command` проверен оболочкой Linux, а не Terminal/Finder macOS. Python-окружение не включено в исходный ZIP; автономного `.exe` в этой поставке нет.

## Источники установки

- [XGBoost 3.4.1 на PyPI](https://pypi.org/project/xgboost/3.4.1/), [CPU-пакет 3.4.1](https://pypi.org/project/xgboost-cpu/3.4.1/): Python ≥3.12 и платформы wheels.
- [LightGBM 4.7.0 на PyPI](https://pypi.org/project/lightgbm/4.7.0/), [официальная инструкция](https://lightgbm.readthedocs.io/en/stable/Installation-Guide.html).
- [CatBoost 1.2.10](https://pypi.org/project/catboost/1.2.10/), [imbalanced-learn 0.14.1](https://pypi.org/project/imbalanced-learn/0.14.1/).
