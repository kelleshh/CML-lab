# Владение контекстами и разработка

CML-lab использует модульный монолит. Один владелец отвечает за изменения внутри контекста; изменение общего договора сначала согласуется с владельцами соседних модулей.

| Направление | Ответственность |
|---|---|
| Архитектура | data, recipes, experiments, execution: инварианты, порты, ревизии и состояния |
| ML | Каталог, численные адаптеры, метрики, CV, поиск и диагностика |
| Data Engineers Consult | Конвейер подготовки, пересэмплирование, feature engineering и ограничения матриц |
| UI/UX | Формы, навигация, библиотека, графики, клавиатура и пояснения |
| Учебные материалы | learning: примеры, формулы, упражнения, источники и устойчивые ссылки |
| Skills и запуск | Выбор применимых навыков, зависимости, запускатели и проверка поставки |
| Тимлид | Общий контракт, интеграция HTTP/хранения/процессов, изоляция данных и выпуск |

## Порядок работы

1. Определить пользовательский сценарий и инвариант. Зафиксировать вход, выход и владельца.
2. Согласовать DTO и зависимости с соседними модулями. Изменение интерфейса сопровождается проверкой обеих сторон.
3. Реализовать сценарий через порты и готовые библиотечные адаптеры.
4. Проверить нормальный результат, реалистичный отказ и границу взаимодействия. Для математического результата нужен независимый расчет.
5. Связать параметры с учебными материалами и обновить действующий договор.
6. Проверить пользовательский путь через HTTP и интерфейс. Выполнить общие проверки и собрать исходную поставку.

Отдельная семья ML расширяет каталог алгоритмов. Она не создает отдельный предметный контекст без собственных состояний и правил. Добавление новых классов не заменяет проверку зависимостей.

При обучении порядок такой: внешнее разделение → обучение подготовки на train → пересэмплирование train → обучение модели → оценка частей. Каждый разрез CV повторяет подготовку и обучение независимо. Итоговые тестовые строки не участвуют в диагностике, поиске и выборе параметров.

Для архитектуры, проверок и документации применяются доступные design-effective-tests и write-engineering-docs. Рекомендации по доступности форм проверяются по [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines), подход к отдельным учебным целям — по [teach](https://github.com/mattpocock/skills/tree/main/skills/productivity/teach). Сторонние наборы навыков не являются зависимостями приложения.
