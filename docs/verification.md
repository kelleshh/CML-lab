# Что и как проверяется

Проверки используют известные численные зависимости, отдельные sklearn-расчеты и публичные HTTP-контракты. Файлы опытов создаются во временных каталогах. Внешние наборы для автоматического прогона подменяются небольшими ответами загрузчиков; обучение, пересэмплирование и экспорт используют настоящие библиотеки.

## Запуск

После подготовки окружения лаборатории:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q tests
```

В Windows замените интерпретатор на `.venv\Scripts\python.exe`. Для интерфейсных проверок нужны Node.js 22.22.2–22.x, 24.15.0–24.x или 26+ (требование jsdom из lock-файла) и зависимости разработки:

```bash
npm ci
node --test tests/frontend.mjs tests/frontend-v2.mjs tests/preprocessing-ui.mjs tests/validation-ui.mjs tests/accessibility.mjs tests/sources-ui.mjs tests/ux-routes.mjs
```

`npm` и Node.js нужны для разработки; обычный запуск лаборатории использует Python. Для диагностики установленного приложения: `python run.py --doctor`. Он проверяет версии, реестр моделей и порт, не запускает сервер и не устанавливает библиотеки.

Методы SMOTER/SMOGN используют четыре включенных сторонних модуля с исправлениями. Тесты известной аффинной зависимости проверяют не только форму матрицы или наличие новых строк, но и значения синтетической цели. Происхождение, версии, лицензии и изменения находятся в [PROVENANCE.md](../linear_lab/_vendor/PROVENANCE.md).

ONNX Runtime получает `ORT_DISABLE_TELEMETRY=1` до импортов расчетных модулей; экспорт также вызывает `disable_telemetry_events()`. Проверка нового процесса подтверждает переменную окружения. Приложение не использует телеметрию Runtime для обучения или экспорта.

## Что проверяют DOM-сценарии

Записанный ответ в `tests/fixtures/qa-fixture.json` получен от настоящих DataService, TrainingService, SearchService и HTTP API: исходные точки, Ridge, подготовка train, повторная CV и попытки Optuna со своей метрикой в обоих направлениях. Переснять данные:

```bash
.venv/bin/python tests/capture_frontend_fixture.py
```

Сценарии исполняют действующие `app.js`, формы, обработчики событий и построение графических трасс. HTTP и публичная отрисовка Plotly заменены тестовыми границами. Это позволяет проверить запросы и содержание графика, не выдавая тестовую имитацию за новый численный расчет.

| Набор | Проверяет |
|---|---|
| `frontend.mjs` | Каталоги, выбор цели/метрик, сравнение, сохранение, редактор страницы, перенос исходной точки |
| `frontend-v2.mjs` | Библиотека, исходные 2D/3D, окраска, простые параметры, помощь и восстановление полного опыта |
| `preprocessing-ui.mjs` | Рецепты, точные настройки, сериализация, реальный до/после и редкая цель |
| `validation-ui.mjs` | Девять CV, группы/время, шесть поисков, параметры и min/max своей метрики, таблицы попыток |
| `accessibility.mjs` | Имена элементов, клавиатура, фокус подсказки, Escape, вкладки и режим уменьшения движений |
| `sources-ui.mjs` | Каталог и фильтры задач, исходная цель класса, метки набора |
| `ux-routes.mjs` | Переходы подсказок к реальным урокам, подготовка/CV/поиск, режим параметров и экспорт |

Часть ответов обычного сравнения в тестовом HTTP-слое задана отдельно для проверки сортировки; она не доказывает качество моделей. Математика моделей проверяется Python-сценариями.

Полный Python-прогон завершился до последнего изменения разрешенного списка файлов ZIP; алгоритмы после него не менялись. Проверки экспорта повторены на окончательном списке. Полный прогон вывел 2356 предупреждений об устаревающих API сторонних библиотек, в том числе старых NumPy-преобразованиях в пересэмплерах и переходе Starlette/httpx; это не численные ошибки. Ранее прерванный запуск не входит в эти результаты. Итоговый прогон использует отключенную телеметрию ONNX Runtime.

## Практические границы проверки

- **Живой браузер:** облачный браузер не смог достичь локального Python-сервера (`ERR_CONNECTION_REFUSED`). DOM-проверки не подтверждают пиксели WebGL, плавность анимации, реальную мышь или совместимость всех браузеров.
- **Windows/macOS:** запускатели включены, но выполнение проверялось на Linux. Проверка shell-аргументов не равна проверке Finder или Windows Terminal.
- **Сеть и наборы:** OpenML и внешние sklearn-источники проверены на подмененных небольших ответах. Доступность удаленного источника, лицензия конкретного набора и скорость скачивания проверяются при его использовании.
- **Установка:** точные зависимости проверяются в текущем окружении; доступность колес для каждой будущей версии Python/ОС не обещается.
- **Производительность:** измерения описывают конкретную Linux-среду, размер таблицы и конфигурацию. Больше потоков не гарантирует ускорение; данные замеров — [performance.md](performance.md).
- **ONNX:** доступность формата относится к конкретной обученной цепочке. Неудачная конвертация не считается успешным экспортом только коэффициентов.

Перед выпуском выполняются полный Python-прогон и семь DOM-наборов, проверяются состав архива, запуск и ссылки документов. Приведенные выше числа относятся к завершенным прогонам; промежуточный или прерванный запуск не служит итогом проверки.
