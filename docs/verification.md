# Проверка CML-lab

Проверки используют временные каталоги, искусственные данные и настоящие ML-библиотеки. Предсказания, метрики и промежуточные состояния сверяются с отдельными расчетами. Сетевые источники проверяются небольшими ответами загрузчиков; это не проверка доступности удаленного сервера.

## Команды

В подготовленном окружении:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q tests
```

Для интерфейсных проверок нужны Node.js и зависимости разработки:

```bash
npm ci
node --test tests/frontend.mjs tests/frontend-v2.mjs tests/preprocessing-ui.mjs tests/validation-ui.mjs tests/accessibility.mjs tests/sources-ui.mjs tests/ux-routes.mjs tests/learning-page.mjs tests/cml-ux.mjs tests/cml-app.mjs tests/cml-plots.mjs tests/cml-api.mjs
```

Семь прежних DOM-наборов проверяют сохраненные модули линейного интерфейса через `linear-index.html`. Активный CML-интерфейс проверяют `cml-app.mjs`, `cml-ux.mjs` и `cml-plots.mjs`; отдельный учебник проверяет `learning-page.mjs`. Это различие важно: прежние проверки компонентов не подтверждают новый пользовательский путь.

В Windows замените интерпретатор на `.venv\Scripts\python.exe`. Требования Node.js описаны в package-lock; обычному пользователю Node.js не нужен.

## Проверяемые сценарии

| Область | Ожидание и проверка |
|---|---|
| Архитектура | Domain/application импортируются без sklearn, pandas, HTTP и SQLite; AST отклоняет обратные зависимости |
| Рецепты и ревизии | Переименование сохраняет параметры; копия сохраняет исходную конфигурацию; устаревший PATCH получает конфликт |
| Запуски | Отмена, завершение, неизменный терминальный результат и монотонное открытие теста |
| Владение папкой | Второй scheduler отклоняется до recovery; закрытие, ошибка и завершение процесса освобождают SQLite lease |
| Ссылки | Сохраненный опыт защищает модель; регистрация расчета и удаление данных синхронизируются между независимыми guard-экземплярами |
| Восемь задач HTTP | Загрузка, настоящий spawn-worker, прогноз/forecast, экспорт, скрытый тест, сохранение, перезапуск и удаление |
| Численные адаптеры | Настоящие библиотечные fit; полный preparation/fit/save-load/raw-inference; неотрицательные методы проверяются с MinMax |
| Подготовка | Статистики только train; новая подготовка внутри CV; сплайны и iterative imputation сверяются со sklearn |
| Категории и текст | Неизвестные категории, пустые столбцы, разреженные TF-IDF и плотные компоненты ансамблей |
| Взаимная информация | Смешанная sparse-матрица не молча считается целиком дискретной |
| Матрицы | Ограничения полиномов, сплайнов, интервалов, календарных признаков и разложений до расширения, включая inference |
| Время и панели | Исторические признаки внутри объекта, разрезы по времени, очистка границ по горизонту; обычный стекинг не допускается |
| Ранжирование | Целые запросы разделяются, qid сортируется, NDCG соответствует экспоненциальной полезности |
| Классификация | Вероятности внутренних групповых разрезов выровнены по внешним классам, включая отсутствующий класс |
| Диагностика | Путь α, кривая размера train и перестановочная важность не используют test и не изменяют экспортируемую модель |
| Графические срезы | Известная плоскость воспроизводится по формуле; диапазоны и закрепленные значения берутся из train; test исключен |
| Экспорт | Joblib/Pickle/Skops/совместимый ONNX проверяются по реальным прогнозам; ZIP запускается в отдельном процессе |
| Обучение | Устойчивые ссылки, известные численные примеры, настоящие преобразования пресетов и успешный startup |
| UI | Все восемь задач, безопасные роли, исходные графики, подготовка, расчет, открытие теста и CRUD через реальные модули с captured API DTO |
| Plotly DTO | Поверхности, области классов, пути штрафов, кривые и полосы ошибок соответствуют численным массивам |
| Запуск | Python и зависимости, порт, собственный manifest, пути с пробелами, повторное открытие, независимость копий и Ctrl+C |
| Упаковка | Все контексты, исходники, тесты и лицензии; кэши, пользовательские файлы, окружение и артефакты исключены |

## Воспроизводимые ответы интерфейса

`tests/fixtures/cml-ui.json` содержит искусственные таблицы и реальные результаты восьми задач, диагностику Ridge и фактическую совместимость экспорта сохраненных моделей. Создать новую запись:

```bash
ORT_DISABLE_TELEMETRY=1 .venv/bin/python tests/capture_cml_ui_fixture.py
```

В DOM-проверках заменяются HTTP и рисующий слой Plotly. Математика считается численным адаптером при создании fixture и отдельно проверяется Python-тестами. Подстановка fetch не подтверждает живую связь браузера с сервером; ее проверяют HTTP-сценарии с настоящим процессом.

## Границы

- Облачный браузер не достигает локального сервера: `ERR_CONNECTION_REFUSED`. В среде также нет Chromium для Playwright. Пиксели WebGL, плавность и работа реальной мышью не подтверждены.
- Нативное выполнение Windows/macOS не проверялось. Linux-запуск распакованного архива, shell-аргументы и платформенные условия зависимостей проверены.
- Проверка зависимостей текущего окружения и `pip --dry-run --no-index` не доказывает установку из пустого окружения на другой ОС.
- Исходники SMOTER/SMOGN содержат исправления исследовательских пакетов и лицензии; предупреждения сторонних API не считаются численными ошибками.
- Координация приложения не защищает от ручного удаления файлов. SQLite и файловая система не образуют общую транзакцию.

Повторные 23 интерфейсные проверки входят в общий набор из 82; результаты не
складываются. Предупреждения численных библиотек остаются в журнале pytest и
не скрываются. Проверка запуска использует готовое окружение и `--system`.
Ограничения браузера и других ОС перечислены выше.

Регрессионные проверки `cml-api.mjs` воспроизводят требование браузерного fetch
к получателю вызова: до исправления загрузка каталога и экспорт давали
`Illegal invocation`. API-клиент привязывает функцию к `globalThis`. Подставной
fetch восьми пользовательских сценариев тоже проверяет получателя. Это
проверка контракта браузерного API; живой браузерный запуск по-прежнему не
подтвержден.
