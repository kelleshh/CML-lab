# Запуск без ручной установки библиотек

Распакуйте весь архив в обычную папку на компьютере. Не запускайте файлы прямо из окна архиватора.

| Система | Что открыть |
|---|---|
| Windows | Двойной щелчок по `start.bat` |
| macOS | Двойной щелчок по `start.command` |
| Linux | `start.sh`: выберите «Запустить в терминале» в файловом менеджере, либо выполните `./start.sh` |

Нужен установленный **Python 3.11 или новее**. Мы проверяли библиотеки в Python 3.12. Если Python отсутствует, окно покажет [официальную страницу загрузки](https://www.python.org/downloads/). На Windows есть отдельный выбор, открывать ли эту страницу. Сам интерпретатор Python автоматически не устанавливается. При установке Python на Windows включите **Add Python to PATH**; установку можно выполнять для текущего пользователя.

После того как Python установлен, запускатель сам создает отдельное окружение `.venv` и устанавливает библиотеки лаборатории из `requirements.txt`. Системные пакеты Python при этом не меняются. Первый запуск требует интернета и может занять несколько минут. В окне видно четыре этапа: проверка Python, подготовка окружения, установка библиотек, запуск сервера. Повторный запуск использует готовое окружение.

Браузер открывается после того, как сервер ответит на проверку готовности. Если автоматическое открытие браузера недоступно, скопируйте адрес из окна. Обычно это [http://127.0.0.1:8765](http://127.0.0.1:8765). Занятый другим приложением порт заменяется ближайшим свободным. Если лаборатория уже запущена, новое окно откроет работающий экземпляр вместо запуска второго сервера.

Чтобы остановить лабораторию, нажмите **Ctrl+C** в окне запуска. Вычисления завершаются вместе с сервером. Закрытие вкладки браузера само по себе сервер не останавливает.

## Если не запускается

Откройте `diagnose.bat` на Windows или `diagnose.command` на macOS. В Linux выполните:

```bash
./start.sh --doctor
```

Диагностика проверяет версии библиотек, загрузку реестра моделей и доступность порта. Она не устанавливает библиотеки и не запускает сервер. До первого обычного запуска сообщение об отсутствующих библиотеках ожидаемо.

Подробности ошибок сохраняются в `~/.linear-lab/launcher.log`. Если настроен `LINEAR_LAB_DATA`, журнал находится в указанной папке. Его точный путь всегда выводится в окне. Журнал установки содержит ошибки pip; перед отправкой журнала проверьте, нет ли в нем личных путей или настроек вашей сети.

| Проблема | Что сделать |
|---|---|
| Python не найден | Установить Python с официального сайта; открыть запускатель снова |
| Не удалось создать `.venv` на Linux | Проверить наличие системного пакета `python3-venv` и право записи в папку проекта |
| Установка библиотек оборвалась | Проверить интернет и подробности в журнале; повторить запуск |
| macOS не разрешает открыть `start.command` | Открыть через контекстное меню Finder; следовать системному сообщению для скачанного файла |
| У `start.sh` или `start.command` нет права выполнения | В терминале в папке проекта выполнить `chmod +x start.sh start.command diagnose.command` |
| Папка проекта или Python перенесены после установки | Удалить только служебную папку `.venv` и запустить снова; данные в папке данных сохранятся |

## Команда для разработчика

```bash
python run.py
python run.py --doctor
python run.py --no-browser --port 9000
python run.py --no-browser --port 0
```

`--check` означает то же, что `--doctor`. `--port 0` выбирает свободный порт автоматически. `--system` использует текущее окружение без автоматической установки библиотек. `--host` меняет адрес сервера; значение по умолчанию ограничивает доступ этим компьютером. Файл `.env` читается как текст настроек, его содержимое не исполняется.

Запускатели используют стандартные средства Python: [venv](https://docs.python.org/3/library/venv.html), [webbrowser](https://docs.python.org/3/library/webbrowser.html) и [документированный запуск Python в Windows](https://docs.python.org/3/using/windows.html). Это не готовый бинарный установщик: Python пока остается отдельным требованием. Windows и macOS запускатели включены в исходники, но проверки выполнения проводились на Linux.
