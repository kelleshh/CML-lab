# Экспорт проекта в Python и Jupyter Notebook

Проект хранит выбор датасета, Pipeline, модель, Tuning, разбиение данных и метрики. Экспорт `.py` или `.ipynb` содержит эти настройки и снимок исходной таблицы. Файл запускает реальный `ExperimentEngine` из исходников CML-lab и сохраняет обученный конвейер. Данные в экспортированном файле остаются такими, какими были при скачивании.

Используйте Python-окружение CML-lab. Эти файлы зависят от модулей `cml_lab` и адаптеров `linear_lab`, а также от библиотек выбранной модели. Одного установленного `scikit-learn` для всех проектов недостаточно: пересэмплирование, ранжирование и временные признаки требуют дополнительных адаптеров.

## Запуск `.py`

Сохраните файл рядом с `run.py` в папке исходников CML-lab. После первого запуска лаборатории зависимости находятся в `.venv`.

Linux и macOS:

```bash
.venv/bin/python my-project.py
```

Windows:

```bat
.venv\Scripts\python.exe my-project.py
```

Каждый запуск создает отдельную папку `cml-project-*` в текущей папке. В ней находятся:

| Файл | Содержание |
|---|---|
| `artifact.joblib` | Модель вместе с обученной подготовкой признаков, метками классов и временными настройками |
| `result.json` | Метрики train и validation, история поиска и доступные исследования |
| `project.json` | Исходный `SPEC`, сведения о происхождении экспорта и версии библиотек |

Папку можно выбрать явно. Если в ней уже есть результат, скрипт прекращает запуск перед обучением и предлагает выбрать другую папку.

```bash
.venv/bin/python my-project.py --output results/experiment-01
```

`--dataset new-table.csv` использует другой CSV вместо встроенной таблицы. В нем должны присутствовать все выбранные признаки, цель и служебные столбцы. Типы этого CSV определяет `pandas.read_csv`; параметры модели и Pipeline остаются сохраненными в `SPEC`.

## Запуск `.ipynb`

Сохраните Notebook рядом с `run.py` в папке CML-lab. Откройте его в Jupyter или VS Code и выберите Python из `.venv` CML-lab. Запускайте ячейки сверху вниз. Ячейки показывают настройки, исходную таблицу, декларацию Pipeline, затем выполняют Tuning, Training и Serialization. Экспорт соответствует формату Notebook 4.5: у ячеек есть уникальные идентификаторы, исходники и пустые outputs до выполнения.

Jupyter нужен только для открытия `.ipynb`; он не требуется для работы лаборатории и `.py`. Установите его в выбранное окружение самостоятельно, если он еще не установлен.

## Что обучается на каких строках

В задачах с учителем движок сначала выделяет train, validation и test. Подготовка признаков и пересэмплирование обучаются на train. В каждой части CV и поиска создается новая подготовка, которая обучается на обучающих строках этой части. Test не участвует в выборе параметров.

Метрики test скрыты в `result.json`. Откройте их явно через `--reveal-test` в `.py` либо `run_project(reveal_test=True)` в Notebook. Не выбирайте параметры по этому итоговому результату.

Clustering, anomaly detection и dimensionality reduction используют всю выбранную рабочую таблицу. Их экспорт сохраняет этот режим и не заявляет оценку новых объектов. Forecasting и panel сохраняют роли времени и объекта, лаги, окна, горизонт и хронологическое разбиение. Ранжирование сохраняет группы запросов. Экспорт не подменяет эти задачи случайным разбиением обычной регрессии.

Декларативная подготовка хранится в `SPEC['preprocessing']['declarative_pipeline']` с форматом `cml.pipeline`, версией `1` и исходником `source`. Исходник описывает вложенные `Pipeline`, `ColumnTransformer` и `FeatureUnion`; его компилирует адаптер CML-lab при обучении. При создании экспорта пользовательский исходник не выполняется.

## Снимки и ограничения

Экспорт сохраненной ревизии проекта использует ее настройки. Экспорт Run или Experiment использует неизменный снимок его настроек. Рецепты моделей и подготовки разрешаются до создания файла; дальнейшее изменение рецепта не меняет скачанный проект.

Встроенная таблица содержит значения, пропуски и типы столбцов в JSON, сжатом gzip и записанном через base64. Это данные, а не `pickle`. Размер JSON ограничен 50 МБ. Версии библиотек записаны в `PROJECT_METADATA`; воспроизводимость между разными версиями библиотек и платформами не гарантируется.

Экспортированный файл повторно выполняет поиск и обучение. Он не является копией ранее обученных весов. Для скачивания уже обученного артефакта используйте экспорт модели в Joblib или ZIP.

## HTTP API

| Запрос | Источник настроек |
|---|---|
| `POST /api/cml/project-exports?format=py` | Текущая конфигурация `{ "name": "my-project", "spec": {...} }` |
| `GET /api/cml/projects/{id}/export?format=ipynb&revision=1` | Сохраненная ревизия проекта |
| `GET /api/cml/runs/{id}/project-export?format=py` | Настройки конкретного запуска |
| `GET /api/cml/experiments/{id}/project-export?format=ipynb` | Настройки сохраненного эксперимента |

Допустимые форматы: `py` и `ipynb`. Ответ содержит файл с `Content-Disposition: attachment`.

Источники форматов и поведения:

- [Jupyter Notebook format](https://nbformat.readthedocs.io/en/latest/format_description.html).
- [scikit-learn: предотвращение утечек данных](https://scikit-learn.org/1.8/common_pitfalls.html#data-leakage).
- [scikit-learn: сохранение моделей](https://scikit-learn.org/1.8/model_persistence.html).
