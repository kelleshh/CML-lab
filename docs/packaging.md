# Проверка и сборка CML-lab

ZIP содержит исходники Python-сервиса, файлы интерфейса, запускатели, инструкции, тесты и лицензии. Python, установленные пакеты и пользовательские данные в архив не входят. Обычный запуск описан в [run-platforms.md](run-platforms.md).

## Зависимости

`requirements.txt` фиксирует 22 прямые зависимости для выбранной платформы и подключает `constraints.txt`. В Linux XGBoost устанавливается как CPU-пакет; в Windows/macOS используется основная дистрибуция той же версии. Условия `sys_platform` выбирают ровно один пакет.

Ограничения фиксируют активное runtime-замыкание проверенного Linux-окружения CPython 3.12: 76 пакетов и дополнительную платформенную запись XGBoost для Windows/macOS. Версии получены из метаданных установленных дистрибуций с обходом обязательных зависимостей; тестовые extras и неиспользуемые `linearmodels` не включены. `setuptools` нужен зависимостям `osqp`.

На другой ОС pip учитывает платформенные условия метаданных и разрешает зависимости, которых нет в проверенном Linux-окружении. Точное Linux-замыкание не является подтверждением установки или выполнения на Windows/macOS.

Проверить подготовленное окружение:

```bash
python -m pip check
python -m pip install --dry-run --no-index -r requirements.txt
python run.py --system --doctor
```

Первый запуск обычного пользователя требует доступа к индексу пакетов. `--dry-run --no-index` проверяет уже установленные пакеты; эта команда не проверяет установку из пустого окружения.

## Состав исходного архива

В корне включаются явно выбранные инструкции, требования, запускатели, настройки разработки и `.env.example`. Каталоги `cml_lab`, `linear_lab`, `web`, `docs`, `tests`, `tools` содержат выбранные исходники и ресурсы. Все пять предметных контекстов CML-lab включаются, в том числе `contexts/data` и `contexts/experiments`.

`linear_lab` сохраняет численные совместимые адаптеры. Реализации SMOTER/SMOGN в `linear_lab/_vendor` включаются с происхождением, исходными хешами и полными лицензиями. Состояние пользователя не становится частью этих исходников.

Сборщик исключает `.venv`, `node_modules`, кэши, runtime-каталоги данных/артефактов, `.env`, журналы, таблицы пользователей и файлы обученных моделей. JSON исходников и воспроизводимые тестовые fixtures включаются. Символические ссылки в выбранном дереве отклоняются до чтения содержимого. В архиве нет пользовательского Python-окружения или готового отдельного бинарного приложения.

Проверить состав:

```bash
python tools/package_source.py --check
```

Создать ZIP вне папки проекта:

```bash
python tools/package_source.py --output ../CML-lab.zip
```

Старое имя команды `tools/package_release.py` вызывает тот же сборщик. Все пути ZIP начинаются с `CML-lab/`.

Запускатели `start.sh`, `start.command`, `diagnose.command` должны иметь право выполнения перед сборкой. ZIP создается во временном файле; сборщик проверяет CRC и сохранение прав, затем атомарно заменяет выходной архив. Архиваторы могут по-разному восстанавливать Unix-права; при необходимости используйте команду `chmod` из инструкции запуска.

Проверки:

```bash
python -m pytest -q tests/test_packaging.py tests/test_launcher.py
```

Проверки включают исключение приватных файлов, запрет символьных ссылок, сохранение bounded contexts, путей с пробелами, аргументов запускателей, выбора платформенных зависимостей и управление локальным сервером. Графическое выполнение WebGL проверяется отдельно; выдача HTML по HTTP не подтверждает отрисовку графиков.
