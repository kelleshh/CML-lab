# Проверка и сборка исходников

Архив содержит Python-сервис, локальные файлы интерфейса, запускатели, инструкции, тесты и лицензии включенных библиотек. Python, установленные пакеты и пользовательские датасеты в архив не входят. Порядок обычного запуска описан в [launch.md](launch.md).

## Зависимости

`requirements.txt` фиксирует 18 библиотек приложения и подключает `constraints.txt`. Ограничения содержат 61 пакет: прямые зависимости и их активные транзитивные зависимости в проверенном окружении CPython 3.12 на Linux x86_64. Версии получены из метаданных установленных пакетов; зависимости необязательных extras не включены.

`pip`, `pytest`, `httpx` и пакеты, необходимые только тестам, в runtime-ограничения не входят. `setuptools` включен, потому что его требует установленный решатель `osqp`. На другой системе pip учитывает платформенные маркеры зависимостей. Платформенные пакеты, отсутствующие на Linux, отдельными версиями здесь не закреплены.

Проверка готового окружения:

```bash
python -m pip check
python -m pip install --dry-run --no-index -r requirements.txt
python run.py --system --doctor
```

Второй вызов проверяет соответствие уже установленного окружения требованиям, без обращения к индексу. Он не подтверждает, что установка из пустого окружения пройдет без интернета. Для первого запуска обычного пользователя запускателю требуется доступ к индексу Python-пакетов.

## Состав архива

В корне включаются явно перечисленные файлы: инструкции, требования, запускатели, настройки Vite, описание пакета, `.env.example` и `.gitignore`. Из каталогов `linear_lab`, `web`, `docs`, `tests`, `tools` включаются исходники и локальные ресурсы интерфейса. Исправленные исследовательские реализации SMOTER/SMOGN включаются вместе с `PROVENANCE.md`, версиями, хешами исходников и полными лицензиями в `linear_lab/_vendor`.

Сборщик исключает окружения Python, `node_modules`, кэши, папки данных, сохраненных экспериментов и артефактов. Файл `.env`, журналы, таблицы пользователей и экспортированные модели также не включаются. JSON в исходниках и синтетические тестовые fixtures остаются частью проекта. Символические ссылки в выбранном дереве отклоняются до чтения их содержимого.

Проверить состав без создания архива:

```bash
python tools/package_release.py --check
```

Создать архив вне папки проекта:

```bash
python tools/package_release.py --output ../linear-lab.zip
```

Сборщик сначала проверяет исходники и права выполнения `start.sh`, `start.command`, `diagnose.command`. Затем создает временный ZIP, проверяет CRC содержимого и сохраненные права запускателей и заменяет указанный выходной файл. Все пути внутри архива начинаются с `linear-lab/`. Права выполнения сохраняются в ZIP; конкретный архиватор на Windows может не восстанавливать Unix-права при последующем переносе файлов на macOS/Linux.

Проверки сборщика и запускателя:

```bash
python -m pytest -q tests/test_packaging.py tests/test_launcher.py
```

## Выполненная проверка запуска

На Linux с CPython 3.12 проверена отдельная копия выбранных исходников в папке с пробелами в имени. В копии отсутствовали `.venv`, `node_modules`, `.env` и пользовательские данные; для проверки использовался уже подготовленный внешний интерпретатор с параметром `--system`. Папка `LINEAR_LAB_DATA` создавалась отдельно и была пустой перед запуском.

Реальный запуск `run.py --system --no-browser --port 0` подтвердил:

- Ответ `/api/health` с версией `2.0.0`, загрузку HTML и локального файла Plotly.
- Доступность каталога из 29 моделей и 32 уроков.
- Успешную диагностику `--system --doctor`.
- Повторный запуск с той же папкой данных: первый процесс сохранил PID, второй завершился без создания еще одного сервера.
- Остановку по SIGINT, закрытие порта и удаление `running-server.json`.

`pip check` сообщил об отсутствии несовместимых зависимостей. Локальная проверка `pip install --dry-run --no-index -r requirements.txt` завершилась без необходимости установки пакетов. POSIX-запускатели прошли `sh -n`; у всех трех файлов установлен режим `755`.

Установка в полностью пустое окружение и запуск на Windows/macOS в этой проверке не выполнялись. Графическое отображение WebGL в браузере относится к отдельной проверке интерфейса; доступность HTML и файла Plotly по HTTP сама по себе его не подтверждает.
