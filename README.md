# CML-lab

Classic Machine Learning laboratory — локальная лаборатория классического машинного обучения. Интерфейс в браузере помогает выбрать данные, определить задачу, собрать подготовку признаков, настроить алгоритм и исследовать результат. Обучение выполняют реальные scikit-learn, XGBoost, LightGBM, CatBoost, skglm и CVXPY; подбор параметров использует библиотечные методы и Optuna.

## Запуск

Установите **64-битный Python 3.12** с [официального сайта](https://www.python.org/downloads/), распакуйте архив целиком и откройте запускатель:

| Система | Файл |
|---|---|
| Windows | `start.bat` |
| macOS | `start.command` |
| Linux | `start.sh` → «Запустить в терминале», либо `./start.sh` |

Первый запуск создает `.venv` и устанавливает библиотеки; нужен интернет. Браузер открывается после готовности сервера. Адрес выводится в терминале, обычно это [http://127.0.0.1:8765](http://127.0.0.1:8765). Для остановки нажмите **Ctrl+C** в окне запуска. Node.js для работы лаборатории не нужен.

Можно запускать из терминала в папке проекта:

```bash
python run.py
```

На Linux/macOS команда может называться `python3`. Подробная [инструкция запуска](docs/run-platforms.md) описывает диагностику, папку данных, перенос прежних датасетов и проблемы нативных библиотек. Windows/macOS имеют свои запускатели; их выполнение в Linux-среде не проверяется.

## Первый проект

1. Откройте **«Датасеты»**, загрузите CSV/Excel или создайте пример. Нажмите **«Использовать»**.
2. В **«Проект» → Data** выберите задачу, цель и признаки. Для ранжирования укажите запрос, для ряда — время, для панели — время и объект.
3. В **Analysis** посмотрите основные распределения, пропуски и корреляции. Дополнительные графики создаются по кнопке с выбранными столбцами и параметрами; доступно 20 видов анализа.
4. В **Pipeline** выберите sklearn Pipeline. Соберите вложенные `Pipeline`, `ColumnTransformer`, `FeatureUnion` графически или напишите декларацию Python. Код подсвечивается; Tab/Ctrl+Space предлагает дополнения, Ctrl+Enter применяет декларацию. «Исходники» в контекстном меню показывает код установленного sklearn. Предпросмотр вычисляет реальные преобразованные значения.
5. В **Estimator** выберите алгоритм. Названия классов и параметров соответствуют английскому API. Все параметры доступны, advanced раскрывается отдельно; поиск находит нужное поле, сохраняя его значение.
6. В **Tuning** выберите метрики, разделение и CV. Search breadth создает редактируемую сетку Tiny–Wide. Можно задать списки JSON, числовые или логарифмические диапазоны и параметры вложенного Pipeline через `pipeline__…`. Показан бюджет проб и обучений.
7. Нажмите **«Запустить расчет»**. В **Training** сравните train и validation, исследуйте результат. Итоговый test открывайте после выбора модели.
8. В **Serialization** скачайте текущий проект `.py` или `.ipynb` либо обученный `.joblib`. Проект содержит данные и конфигурацию и запускается в окружении CML-lab. В библиотеке сохраняются неизменные снимки завершенных запусков.

Каждое поле содержит `?` с русским объяснением и переходом к своему материалу в новой вкладке. **Ctrl+S** сохраняет проект; в **«Моя библиотека»** находятся проекты, модели, datasets и Pipelines с характеристиками и экспортом. Изменение таблицы создает новую версию, удаление защищает данные существующих расчетов.

В каталоге **117 алгоритмов**, **1912 параметров моделей**, **83 класса декларативного Pipeline** и **2911 учебных материалов**. Прежний конструктор с **25 этапами подготовки** сохраняется как Legacy steps. Колонка настроек регулируется от 360 до 760 px; интерфейс использует кремовую, графитовую и бордовую палитру. Пошаговое [руководство](docs/guide.md) описывает сценарии.

## Задачи

| Задача | Что делает модель |
|---|---|
| Регрессия | Предсказывает числовую цель. |
| Классификация | Предсказывает категорию; совместимые алгоритмы возвращают вероятности классов. |
| Кластеризация | Находит группы без обучения по правильным меткам. Известные классы можно отдельно использовать для оценки. |
| Ранжирование | Упорядочивает объекты внутри одного запроса. Запросы целиком разделяются между частями данных. |
| Временной ряд | Использует доступные прошлые значения, лаги и окна для прогноза более позднего значения. |
| Панельные ряды | Строит временные признаки отдельно для каждого объекта и обучает выбранный регрессор. |
| Поиск аномалий | Выделяет наблюдения, отличающиеся от обычных данных. |
| Снижение размерности | Строит более компактное представление признаков для просмотра и анализа. |

Семейства алгоритмов включают линейные модели и штрафы, деревья, леса, бустинг, ансамбли, соседей, SVM, наивный Байес, дискриминантный анализ, гауссовские процессы, смеси, методы плотности, иерархии и разложения. Каталог показывает фактическую доступность адаптера и причину ограничения. Полный [каталог алгоритмов](docs/algorithm-catalogue.md) описывает семьи и свойства.

## Данные, рецепты и результаты

| Объект | Что сохраняется и редактируется |
|---|---|
| Датасет | Исходная таблица, описание, задача и характеристики. Изменение строк или описания создает новый снимок; исходный сохраняется. |
| Шаблон модели | Зарегистрированный алгоритм и его параметры. Изменение создает ревизию. |
| Pipeline | Декларация sklearn, вложенные преобразования, маршруты признаков и overrides; доступны `.py` и формат `cml.pipeline` в `.json`. |
| Проект | Настройки полного эксперимента: данные, задача, модель, подготовка и проверка. |
| Запуск | Снимок настроек, состояние процесса и результат расчета. |
| Обученная модель | Полный обученный конвейер, связанный с завершенным запуском. |

Новые модели собираются формами из доступных адаптеров; Pipelines редактируются как Python и как графическое дерево. Настройки можно сохранять, применять, обновлять, копировать и удалять. Конфликт ревизий отклоняет сохранение устаревшей формы. Прошлый эксперимент сохраняет собственный снимок, поэтому обновление шаблона не меняет выполненный расчет.

Данные импортируются из таблиц, встроенных sklearn-наборов, генераторов и OpenML. Большие или нетабличные источники показывают ограничения адаптера; сетевые источники требуют доступного сервера. Каталог не превращает неподдерживаемый формат в случайную таблицу.

Подготовка включает пропуски, масштабы, числовые преобразования, категории, текстовые и календарные признаки, взаимодействия, отбор и снижение размерности. Пересэмплирование выполняется только там, где подходит тип цели и выбранная проверка. Статистики обучаются на обучающей части; внутри каждой части перекрестной проверки преобразования обучаются заново.

Итоговый тест скрыт до явного открытия. Выбор параметров использует обучающую часть и внутреннюю перекрестную проверку. Для временных задач порядок сохраняется; для панелей лаги не переходят между объектами.

Проекты экспортируются в `.py` и `.ipynb`, Pipeline — в `.py` и собственный формат JSON. Форматы обученной модели включают Python-артефакты, паспорт, CSV/JSON результата и архив с исходниками. Совместимые форматы определяются для конкретного конвейера; интерфейс показывает причину, если преобразование или алгоритм не поддерживают формат. Метод без переноса на новые строки не получает выдуманный `predict`.

## Границы методов

Временная оценка идет пошагово: для нового момента используются уже доступные прошлые наблюдения. Это нужно учитывать при сравнении с задачей одновременного прогноза всего будущего блока. Панельный маршрут строит признаки внутри объекта; конкретную статистическую модель выбирают отдельно.

Декларативный редактор принимает зарегистрированные классы и литералы, селекторы и разрешенные функции NumPy. Произвольные Python callbacks, циклы, `exec`, `eval`, metadata routing и файловый ввод не поддерживаются. Полная схема и границы описаны в [Pipeline](docs/pipelines.md).

Некоторые методы кластеризации и вложения описывают только обучаемую таблицу. Возможность обработки новых строк указана в каталоге. Дорогие алгоритмы имеют ограничения по строкам и размеру матрицы; причины возвращаются пользователю до неконтролируемого выделения памяти.

Промежуточные состояния показываются, когда адаптер действительно их записывает. Готовый результат метода без истории не выдается за анимацию оптимизации. Выполнение WebGL и визуальная плавность требуют проверки в настоящем браузере.

Для регрессии и классификации доступны срезы модели по выбранным числовым признакам. Для подходящих моделей можно включить путь регуляризации, кривую качества по размеру train и перестановочную важность. Дополнительные исследования используют train/validation; неподдерживаемые временные или групповые сочетания показывают причину ограничения.

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q tests
```

В Windows используйте `.venv\Scripts\python.exe`. Разработке интерфейса нужны Node.js подходящей версии и `npm ci`; обычный запуск готового интерфейса использует файлы без Node.js.

Сборка исходного архива вне папки проекта:

```bash
python tools/package_source.py --check
python tools/package_source.py --output ../CML-lab.zip
```

Архив содержит исходники, ресурсы, запускатели, тесты и лицензии. Локальные окружения, данные пользователей, артефакты и секретные настройки не включаются. Команды и правила состава — в [инструкции упаковки](docs/packaging.md).
